# 剧本：降魂仪式（ritual）

- 状态：已实现，可完整游玩；平衡严重偏英雄，叛徒分支在正常对局中几乎不出现；存在「遗骸在煤槽」必输地图
- 代码：`scenarios.js:5`（配置）、`engine.js:59, 76–81, 162`（仪式、召唤、安葬、驱散、幽灵、崩塌、胜负）
- 来源：v0.3 §31.2 / Haunt #2 的结构适配（非官方文本复刻）

## 1. 概述

作祟后理智最低者成为叛徒。英雄与叛徒在任意房间做仪式检定，先攒满进度的一方得到幽灵的控制权，然后剧本分叉：

- **英雄控制 → 安葬**：找到遗骸、运到安葬点，时限内完成即胜；叛徒要拦截或拖到超时。
- **叛徒控制 → 崩塌**：幽灵追杀英雄，房屋边缘逐轮崩塌；英雄要和幽灵同房、用理智驱散它 3 次。

## 2. 玩家体验目标

- 仪式阶段是一场「谁先拿到幽灵」的拉锯，双方都有机会，局面一翻两瞪眼。
- 两个分支体验截然不同：安葬是护送与拦截，崩塌是在收缩的房子里被追杀后反击。
- 叛徒虽然人少，但单次成功价值更高（+2），应当有真实的翻盘机会。——当前未达成。

## 3. 详细规则（与代码一致）

### 3.1 仪式竞速（阶段 `ritual`）

1. 每名存活角色每回合可做一次「仪式」任务，**任意房间**都行，选知识或理智（含典籍 / 护符加成）。
2. 总和 ≥ 4 即成功：英雄方进度 +1，叛徒方进度 +2；失败也消耗本回合任务次数。
3. 任一方进度 ≥ 3 时立即召唤幽灵，归该方控制，剧本转入对应分支（`engine.js:76–77`）。
4. 此阶段**不能攻击**（`engine.js:78` 只在 burial / collapse / rescue 允许）。移动、开门、用物品照常。
5. 行动顺序：英雄按座位在前，叛徒最后。
6. 如果叛徒在此阶段死亡（只可能因事件伤害），幽灵自动归英雄（`engine.js:162`）。

### 3.2 英雄分支：安葬（阶段 `burial`）

1. 召唤时幽灵出现在召唤者所在房间；在此分支幽灵**不行动**（`ghostTurn` 只在 collapse 生效）。
2. 遗骸房：从已发现、未崩塌、且不是召唤者当前所在房间的房间中**随机**选一间。
3. 安葬点：已发现的「墓穴」；没发现墓穴则用**地下平台** `-1:0:0`。
4. 在遗骸房做「寻找遗骸」任务：知识 ≥ 4，成功者成为携带者；失败可下回合再试。
5. 携带者在安葬点做「安葬」任务：**不掷骰**，直接获胜。
6. 时限：`countdown = 6`；召唤当轮不扣，此后每个轮末 −1，归零叛徒胜（`engine.js:81`）。
7. 叛徒可以攻击同房英雄（每回合一次，力量对抗）。携带者死亡时遗骸掉在原地，需要重新搜索。
8. 所有英雄死亡 → 叛徒胜。叛徒死亡不结束游戏。

### 3.3 叛徒分支：崩塌（阶段 `collapse`）

1. 幽灵出现在叛徒当前所在房间。
2. **驱散**：英雄与幽灵同房时，可用本回合的攻击次数驱散——英雄掷理智（含护符），幽灵掷 4 骰，严格大于为成功：驱散进度 +1 并击晕幽灵；幽灵大 → 英雄受差值精神伤害；平局无事。累计 3 次成功英雄胜（`engine.js:78`）。
3. **幽灵行动**（每轮最后一名角色行动后、轮末结算前，`engine.js:80, 83`）：
   - 被击晕：解除击晕，本轮不行动。
   - 否则：找路径最近的存活英雄，掷 2 骰决定移动步数（0–4 步），沿最短路径前进；如果进入目标所在房间，幽灵掷 4 骰对英雄理智（含护符）：幽灵大 → 差值精神伤害；英雄大 → 幽灵被击晕；平局无事。
4. **崩塌**（轮末，`engine.js:81`）：在未崩塌、非保护、且只有 ≤ 1 个相邻房间的「叶子房间」中随机选一间；房内所有角色（包括叛徒）受 1 点物理伤害并被推到唯一出口，然后该房间永久崩塌。保护房间：入口大厅、大楼梯、上层平台、地下平台、幽灵当前所在房间。没有合格房间的轮次不崩塌。
5. 叛徒可以攻击英雄。未被击晕的幽灵同房时，英雄离开要多花 1 移动力。
6. **没有时限**。叛徒只能靠杀光英雄获胜。

### 3.4 胜负一览

| 结局 | 条件 |
|------|------|
| 英雄胜 | 携带者在安葬点执行安葬；或驱散幽灵累计 3 次 |
| 叛徒胜 | 安葬时限归零；或所有英雄死亡 |

## 4. 公式与参数

- 仪式单次成功率（总和 ≥ 4）：3 骰 37%、4 骰 62%、5 骰 79%、6 骰 89%。
- 英雄方需要 3 次成功；叛徒方需要 2 次成功。英雄每轮有 (n − 1) 次尝试，叛徒 1 次，且英雄先手。
- 驱散单次成功率（理智骰 vs 4 骰，严格大于）：4 骰 42%、5 骰 58%、6 骰 72%。
- 幽灵移动步数 = 2 颗 0/1/2 骰之和：0 步 11%、1 步 22%、2 步 33%、3 步 22%、4 步 11%。

探针数据（全 AI、默认阵容、正常开局，每档 100 局）：

| 人数 | 英雄拿到控制权 | 叛徒拿到控制权 | 仪式平均持续（轮，不含作祟当轮） |
|------|----------------|----------------|----------------------------------|
| 3 | 88% | 12% | 1.1 |
| 4 | 100% | 0% | 0.65 |
| 5 | 100% | 0% | 0.32 |
| 6 | 100% | 0% | 0.10 |

6 人局里，仪式通常在作祟当轮就结束了，叛徒往往一次仪式都没掷到。400 局总体：英雄胜 97%（安葬成功 370、驱散成功 6），叛徒胜 3%（英雄全灭 12、安葬超时 1）。

## 5. 边界情况

1. **遗骸在煤槽 → 必输**：遗骸房随机时没有排除煤槽，进入煤槽会立刻滑到地下平台，永远无法在煤槽里做任务。探针中约 3% 的对局出现，英雄 0/11 获胜。
2. **安葬点高度重复**：墓穴只出现在地下且是预兆房，探针中 82% 的对局没发现墓穴，安葬点退回地下平台。快速开局预置了墓穴，所以快速开局的安葬点永远是墓穴——快速开局和正常开局的这段体验不同。
3. **遗骸房可以就是安葬点**：随机时只排除召唤者所在房间，所以遗骸可能直接出现在墓穴 / 地下平台，找到即可在下回合安葬。
4. **遗骸房距离不受控**：随机选取不考虑距离，可能在隔壁，也可能在对面楼层尽头，安葬难度的方差很大。
5. **叛徒在安葬阶段死亡**：游戏继续，英雄照常运送，只剩时限这一个阻力。
6. **崩塌无叶子房间**：该轮不崩塌；保护房间包括幽灵所在房间，所以幽灵站的地方不会塌。
7. **崩塌伤害打到叛徒**：崩塌对所有在场角色一视同仁，叛徒也会因此死亡；叛徒死亡不影响崩塌分支继续。
8. **崩塌阶段的 `countdown`**：召唤时被设为 6，但崩塌阶段不递减、界面也不显示，是遗留字段。
9. **文案写死**：仪式开场说明（`engine.js:59`）、检定反馈（`engine.js:76` 里写死「≥ 4」「+1 / +2」「/3」）、召唤说明（`engine.js:77`「知识 ≥ 4」「6 个完整轮次」「4 骰防御」「3 次」）、目标栏（`intel.js`「3 点」「/3」「4 骰」）、变化回顾（`awareness.js`「/ 3」）、规则说明（`app.js`）都没有读配置。**改 `scenarios.js` 的数值前，必须先让这些文案读配置**，否则说明和结算会不一致。

## 8. 验收标准

1. 3–6 人、正常开局与快速开局都能打到结局，不存在必输地图（遗骸房、安葬点必须是能停留的房间）。
2. 两个分支在正常对局中都能自然出现，出现比例落在一个设计区间内（区间待 QA 数据后与用户商定）。
3. 各人数下的英雄胜率落在目标区间内（待定），且随人数变化不应单调偏向一方。
4. 所有界面上出现的门槛、目标、时限、骰数与 `scenarios.js` 配置一致（改配置后界面自动跟随）。
5. 安葬时限、驱散进度、幽灵位置在目标栏、地图和轮末预告中始终同步。（已有测试覆盖大部分）
